# THE MINT LISTING: every catalog entry tools/stick_mint.py may mint into the box's keeping (run 2026-11-13-stick-ship).
# One entry per line:
#
#   NAME ENTRY_SHA256 [KEY=HASH]... [expect=present|expect=refused]
#
# NAME is a DATA entry of the catalog, data/sticks/NAME.json, of the form [a-z0-9][a-z0-9_]* as the catalog's file
# stems are, and the only thing `sh tools/deploy.sh --mint`, `--mint-check` and `--mint-retract` take; a handler entry
# is refused, since its run is Python in tools/tick.py. ENTRY_SHA256 is the sha256 of that file's bytes with CR LF as
# LF. Each KEY=HASH is one of the entry's seals, in the entry's order and every seal listed, with the content hash it
# must mint, computed by running the entry in an isolated keeping in the environment tools/tick_golden.py uses (a fresh
# temporary CONCORDANCE_DATA_DIR, CONCORDANCE_SEAL_INDEX=0, CONCORDANCE_VERIFY_TIMEOUT_S=1800,
# CONCORDANCE_RIEMANN_MAX=1e9, WEB_FIND_DISABLED=1); the step that adds an entry computes them and its checker
# reproduces them. An optional last token, expect=present or expect=refused, marks a canary, which is never retracted.
# A comment line just before each entry says what it mints and why.
